# What this tool is

[![skills.sh](https://skills.sh/b/Merlon-Docs/merlon)](https://skills.sh/Merlon-Docs/merlon)

**Merlon Docs** is a **documentation system** delivered as an [Agent Skill](https://agentskills.io) plus a small compile/check toolchain. It is for **software projects** whose product documentation must stay **reviewable and structurally sound** as the code changes — especially for teams and agents who **operate the system for the long haul**, not for the engineer who keeps the whole scope in their head. **Accuracy** of what the docs say is a **human and agent** responsibility in review; **`merlon check`** validates links, compile output, and related gates, not whether the claims are true. If you are comparing it to other skills on [skills.sh](https://skills.sh) (for example LLM Wiki or aDNA-style vaults), [What kind of Agent Skill is this?](./kind-of-agent-skill.md) places it in that category and shows how to wire it through your project's `AGENTS.md`. If you are evaluating it for a team, [Vision and roadmap](../features/system/00-vision-and-roadmap.md) explains the problem it solves and the principles behind it.

Merlon Docs, formerly MDCP (MarkDown Context Protocol), is an open standard and an open-source project, MIT licensed.

Instead of putting every architecture note and spec into one file, Merlon Docs stores that intent as small, validated Markdown **shards** such as `docs/features/my-feature.md`, `docs/procedures/line-changeover.md`, `docs/equipment/press-manual.md` or `docs/training/onboarding-module.md`. The Agent Skill tells agents to read **one shard at a time** and to update the shards before they change what the shards describe. In CI, `merlon check` fails when a shard is orphaned or an internal link is broken. Discover and install via [skills.sh](https://skills.sh/Merlon-Docs/merlon). <!-- merlon-paths: illustrative -->
