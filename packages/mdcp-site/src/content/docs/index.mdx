## The guardrail under your helper skills

Agents pick up helper skills for each task, such as planning, test-driven development or code review. Those skills change the code. MDCP is the skill that fails the change when the docs no longer match it, so it belongs in every repository whichever helpers you add.

## What MDCP is

Docs live in a `docs/` folder as small Markdown files called shards, one topic per file, grouped into guides by who reads them.

```text
docs/
├── mdcp.config.json
├── features/    what the product does and why
├── client/      install and usage for the people who use it
├── developer/   setup and workflow for contributors
└── glossary/    one term per file
```

From there the protocol does two things. **Compile** stitches each guide's shards into the README or guide that readers open on GitHub and npm. **Check** runs in CI and fails when a link points at a missing file or heading, or when a compiled file no longer matches its shards. The [quick start](./guide/install-and-quick-start/) has the commands.

## Governance and evidence

MDCP is young, so this page doesn't claim adopters. You can verify these today:

- **A versioned specification.** [MDCP 1.0](./concepts/protocol/mdcp-10-spec/) is a draft written with RFC 2119 keywords. The protocol version moves separately from package releases.
- **Public decisions.** Design choices are recorded as [architecture decision records](./concepts/adr/), including the ideas that were turned down.
- **An evidence policy.** Public copy follows a [claims policy](./concepts/protocol/benefit-claims-and-evidence/) that bans unmeasured outcomes, and [research records](./concepts/protocol/research/about-research-records/) keep what was measured.
- **Built with itself.** This site and the repository's READMEs compile from MDCP shards, and `mdcp check` runs in this repository's CI.

## Questions

<details>
  <summary>Does MDCP replace my other skills?</summary>

No. Helper skills plan, write and review code. MDCP keeps the docs about that code accurate. Install both.

</details>

<details>
  <summary>Do I need the agent skill to use it?</summary>

No. The `mdcp` CLI compiles and checks docs on its own, in CI or locally. The skill adds the instructions an agent follows to update shards as it works.

</details>

<details>
  <summary>Which agents does it work with?</summary>

Any host that supports [Agent Skills](https://agentskills.io), including Claude Code, Cursor and GitHub Copilot.

</details>

<details>
  <summary>Is MDCP an MCP server?</summary>

No. The Model Context Protocol connects agents to live tools and data. MDCP works on files in your repository and runs in CI. See [scope and positioning](./concepts/protocol/01-scope-and-positioning/).

</details>
