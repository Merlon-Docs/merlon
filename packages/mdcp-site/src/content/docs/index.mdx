## A keystone among your helper skills

Agents pick up helper skills for each task, such as planning, test-driven development or code review. Those skills help finish the task in front of them. MDCP looks after what outlasts the task, from the intent behind a feature to how the system is built and operated. It is the guardrail that has a project write that down while the work happens, so it belongs in every repository whichever helpers you add.

Keeping docs accurate takes three parties, and MDCP gives each one a job:

## Organize docs once, write for every reader

Docs live in a `docs/` folder as small Markdown files called shards, one topic per file. Guides list which shards they include and in what order, and `mdcp compile` assembles each guide into the README or handbook its reader opens.

```text
docs/
├── mdcp.config.json
├── features/    what the product does and why
├── client/      install and usage for the people who use it
├── developer/   setup and workflow for contributors
└── glossary/    one term per file
```

Because the primary docs are already split by topic, a new perspective is a new guide over existing shards. Drafting a customer guide from the same shards, or reviewing the whole set, takes a language model little time. It starts from organized source instead of scattered notes.

## Beyond engineering docs

The default layout is built for software, but the same shards and guides work for any team that writes its knowledge down as text. Product development, marketing, sales, user experience and design notes all fit, as long as the source isn't a canvas.

Teams that design in a canvas tool such as Figma still have reasoning that reads better as text, such as the decision behind a layout or the steps a user follows through a flow. Kept as shards, that text becomes the raw material for a help center or user documentation site.

## Where MDCP stands

MDCP is useful today and still being refined. The specification is a draft, and the process and skill keep improving from what real use shows.

On a [repository where agents wrote every commit](./concepts/protocol/research/field-report-automated-repository/), the structural checks held: every shard was indexed and no broken internal link reached trunk. The agents produced useful documentation, but it sprawled, with seven shards past 300 lines and one guide still describing a component that had been removed. A person used the skill's doc-review workflow to reorganize it. That gap between structure and meaning is what current work on the protocol and the skill targets.

You can verify the rest:

- **A versioned specification.** [MDCP 1.0](./concepts/protocol/mdcp-10-spec/) is a draft written with RFC 2119 keywords. The protocol version moves separately from package releases.
- **Public decisions.** Design choices are recorded as [architecture decision records](./concepts/adr/), including the ideas that were turned down.
- **An evidence policy.** Public copy follows a [claims policy](./concepts/protocol/benefit-claims-and-evidence/) that bans unmeasured outcomes, and [research records](./concepts/protocol/research/about-research-records/) keep what was measured.
- **Built with itself.** This site and the repository's READMEs compile from MDCP shards, and `mdcp check` runs in this repository's CI.

## Questions

<details>
  <summary>Does MDCP keep docs in sync with the code automatically?</summary>

Not by itself. The CLI checks that docs refer to each other and to files correctly. Whether the prose still matches the code depends on an agent following the skill and a person reviewing the change.

</details>

<details>
  <summary>Does MDCP replace my other skills?</summary>

No. Helper skills plan, write and review code. MDCP records what the project needs to remember about that code. Install both.

</details>

<details>
  <summary>Do I need the agent skill to use it?</summary>

No. The `mdcp` CLI compiles and checks docs on its own, in CI or locally. The skill adds the instructions an agent follows to update shards as it works.

</details>

<details>
  <summary>Which agents does it work with?</summary>

Any host that supports [Agent Skills](https://agentskills.io), including Claude Code, Cursor and GitHub Copilot.

</details>

<details>
  <summary>Is MDCP an MCP server?</summary>

No. The Model Context Protocol connects agents to live tools and data. MDCP works on files in your repository and runs in CI. See [scope and positioning](./concepts/protocol/01-scope-and-positioning/).

</details>
